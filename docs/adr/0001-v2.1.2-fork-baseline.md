# ADR 0001 — Rebase the fork on v2.1.2 and make the current state `main`

- Status: Accepted
- Date: 2026-10-21
- Deciders: fork maintainer

## Context

The installed TUI is `opencode v2.0.12.r18154.g6c016fd40d`, built from
`upgrade-v2` at `v2.0.12-6-g6c016fd40d`. The latest stable tag is `v2.1.2`
(`a517687fde`). The next tab-organization work depends on plugin APIs that
first appeared after 2.0.12, and the TUI workspace is shared by multiple
devices through SSH.

The six local commits on top of `v2.0.12` are:

1. `2a4b9aa476` — vendor `opencode-agent-tui` config editor
2. `519cbc0fd7` — agent-tui gear plugin in the prompt footer
3. `bf63edeab2` — show session id in subagent messages
4. `d07fdb0c2b` — docs: rebase fork on v2.0.12 and ignore `.codegraph`
5. `8db30dde4e` — default local agents to `deepseek/deepseek-flash`
6. `6c016fd40d` — complete declared command arguments

The public fork cannot be made private: GitHub ties a fork's visibility to its
upstream, and the upstream is public. Personal harness material therefore does
not belong in the fork.

## Decision

- Target the `v2.1.2` release tag exactly. Do not target `upstream/dev` (31
  commits past the tag) or `upstream/beta` (unreleased, divergent).
- Make the current state the baseline:
  - tag the six feature commits as `fork-features-2026-10-21`;
  - commit the harness removal to the public fork;
  - create `main` at that state;
  - make `main` the fork's default branch and the PKGBUILD source.
- Create `upgrade-2.1.2` from `main`; cherry-pick the six feature commits;
  add the `/clear` change; verify; merge back to `main` only after the trial
  passes.
- Preserve all six local commits. Port the agent-tui gear plugin first because
  the TUI plugin API is the most likely to have changed.

## Alternatives considered

- **v2.0.32** — last 2.0.x and the safest match for tab plugins built against
  OpenTUI 0.5.17, but the user chose the latest stable line.
- **`upstream/dev`** — newer than the release, but unreleased and not a stable
  target for a daily driver.
- **`upstream/beta`** — contains unreleased GUI tab work that does not apply to
  a TUI-only user, and is diverged from `dev`.
- **Separate stock 2.0.32 trial** — lower risk, but does not produce the
  desired single daily-driver branch.

## Consequences

- The port spans roughly 2,370 commits and may conflict in TUI prompt,
  builtins, and session-route files.
- The daily driver remains on 2.0.12 until `upgrade-2.1.2` is verified and
  merged.
- v2.1.2 uses OpenTUI 0.6.6; tab plugins built against OpenTUI 0.5.17 require a
  trial before they are trusted.
- The three new core DB migrations (`project.time_active`,
  `azure_cli_external_credential`, `project.time_archived`) run on first
  launch. A SQLite backup is mandatory before that launch.
- Release tags are snapshots, not linear ancestors of `dev`; use an explicit
  cherry-pick or `rebase --onto`, never a plain `git rebase v2.1.2`.

## Guards

- `opencode --version` must report a v2.1.2-based fork.
- All six local features must still work after the port.
- `/clear` must open a new session at the current session's location; `/new`
  must keep honoring `session.new_location`.
- A 3-day trial must pass before the old build is removed.
- Rebuild instructions for the old commit must be written down before the first
  install.
